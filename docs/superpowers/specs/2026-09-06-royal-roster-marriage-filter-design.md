# 皇嗣名册婚姻筛选与召见机制设计

## 目标

为皇嗣名册增加“总数 / 未婚 / 已婚”筛选，并让名册、序齿、居所、母妃四个视图共享同一筛选状态。普通皇嗣婚后迁居宫外，只有奉召时临时恢复宫内互动；太子婚后仍正式居住毓庆宫，不受宫外召见限制。

## 数据模型

在 `PersonRecord` 中明确保存婚姻与居住状态：

- `maritalStatus`: `UNMARRIED | MARRIED`
- `residenceType`: `PALACE | OUTSIDE_PALACE`
- `isSummoned`: 是否处于临时奉召入宫状态

正式 `residence` 始终表示户籍式住所，不因召见修改。现有旧状态/旧存档通过配偶关系兼容推导；太子身份由 `GameState.crownPrinceId` 判断，避免重复字段造成不一致。

## 领域逻辑

新增共享皇嗣名册领域模块，集中提供：

- 婚姻筛选与三项动态统计
- 当前是否在宫内的判断
- 太子与普通皇嗣的居所分组
- 已婚宫外皇嗣的可用操作
- 跨日清除临时召见状态

普通未婚皇嗣和公主沿用既有居所；未婚/已婚太子均归入毓庆宫；普通已婚皇嗣和公主归入宫外。序齿始终按“太子 / 皇子 / 公主”独立分组，缺少太子时不渲染空分组。

## 状态流转

婚配完成时：

- 普通皇子、公主：`MARRIED + OUTSIDE_PALACE + isSummoned=false`
- 太子：`MARRIED + PALACE + isSummoned=false`，住所保持毓庆宫

召见只允许作用于“已婚且正式住所为宫外”的皇嗣，成功后设置 `isSummoned=true`。详情页的操作由统一 selector 生成：未召见时仅显示召见、赏赐、封爵、问责；奉召后恢复正常皇嗣操作。进入下一日时所有奉召状态归零。

## UI

皇嗣名册每次打开默认选择 `UNMARRIED`，关闭后不保存筛选状态。切换底部四个视图时保留当前筛选。卡片显示婚姻状态和正式住所；详情显示“住所：宫外 / 当前：奉召入宫”等临时状态信息。

母妃视图只显示当前筛选命中的子女，母妃卡片人数使用筛选后的子女数量；没有匹配子女的母妃隐藏。公主与皇子共同计入统计和所有筛选。

## 兼容与边界

- 不通过修改 `residence` 文本实现召见。
- 不把“已婚”简单等同于“宫外”，太子是明确例外。
- 保留现有画像、爵位、齿序、母妃/养母、履历与关系数据。
- 旧数据缺少新字段时由兼容 helper 提供稳定默认值，避免破坏现有测试和存档读取。

## 验证

先为共享领域函数编写失败测试，再实现最小逻辑；随后补充皇嗣名册 UI 测试和现有全量测试、类型检查、生产构建。
